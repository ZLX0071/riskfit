# 决策日志（Decision Log）

记录 0→1 过程中的关键取舍。格式：背景 → 决策 → 理由 → 被放弃的替代方案。

---

**D-01 · 项目方向：为什么是"组合风险体检台"**（2026-10-06）
- 背景：需要一个 risk analysis 主题的作品集项目，服务 HK 的 AI PM / fintech / crypto PM 实习面试。
- 决策：做 AI 组合风险体检工具（多资产输入→计算指标→AI 说人话报告）。
- 理由：一个产品覆盖三类面试叙事——AI 公司看 agent 设计与可靠性，fintech 看风险场景理解，crypto 看资产覆盖与极端行情话题。
- 放弃：港币联系汇率雷达（受众窄、免费数据难）；信贷风控沙盘（静态数据、现场演示感弱）。

**D-02 · V1 范围：纯体检报告，不做穿越沙盘**（2026-10-06）
- 背景：发散出四个增强方向（多智能体委员会、历史穿越沙盘、合规质检员、杠杆清算模拟器）。
- 决策：V1 只做体检报告；委员会与穿越写进 roadmap。
- 理由：求职时效优先（一周工期 vs 一周半）；PM 作品集比判断力不比功能量，砍范围本身是面试素材。
- 放弃：A′（体检+穿越体验作为 v1 主体）。

**D-03 · AI 可靠性：计算与叙述分离**（2026-10-06）
- 背景：LLM 直接生成含数字的报告有幻觉风险。
- 决策：所有数字由代码计算；LLM 只解释；生成后逐数字校验（与计算结果 JSON 对照），失败重试≤2 次后回退确定性模板。
- 理由：把"AI 可靠性"从口号落成工程机制，是本项目最核心的 AI PM 谈资。
- 放弃：让 LLM 直接算数（快但不可信）；不上校验只靠 prompt（无兜底）。

**D-04 · 合规边界："建议"改为"风险提示+自查问题"**（2026-10-06）
- 背景：初版报告设计含"一条可操作建议"，触及无牌投资建议风险（HK SFC 监管敏感区）。
- 决策：改为三个自查问题（如"你的现金储备扛得住一次最大回撤吗"）+ 固定免责声明；AI prompt 硬约束禁止买卖建议措辞。
- 理由：合规不是负担而是差异化——监管意识是 fintech 面试的加分项。

**D-05 · 数据源：crypto 改用 Binance 公开 K 线**（2026-10-06）
- 背景：CoinGecko 免费接口只能取 365 天历史，"2022 币灾用真实数据"会落空。
- 决策：crypto 历史数据改用 Binance 公开 K 线接口（免费、无需密钥、全历史）；CoinGecko 仅作备用。
- 放弃：纯 CoinGecko 方案。

**D-06 · 游戏化：只保留体质分**（2026-10-06）
- 背景：讨论过 heavier 游戏化（穿越沙盘互动、分享卡片）。
- 决策：V1 仅保留"风险体质分 1–10"；分享卡片放 v1.5。
- 理由：demo 场景证明不了留存价值（游戏化的真正回报）；拿真实亏损做娱乐化有观感风险。

**D-07 · 评分卡：五指标加权，权重公开**（2026-10-06）
- 决策：波动率 25% / 最大回撤 20% / VaR 20% / 集中度 20% / 平均相关性 15%，四档分档表内线性插值。
- 理由：评分怎么算是 PM 决策而非黑盒；公开权重 + 标注"可迭代"既是透明度也是面试谈资。
- 开放问题：权重基于访谈洞察的定性判断，待真实用户反馈校准（记入复盘）。

**D-08 · 用户调研：模拟画像先行，真实测试后置**（2026-10-06）
- 背景：求职时效紧，无法先完成充分的真实访谈再开发。
- 决策：先用 6 个假设画像推演需求假设（明确标注非真实用户），上线后 D7 用 5 名真实用户测试验证关键假设（洞察 2：集中度盲区；洞察 5：AI 信任）。
- 理由：假设先行的成本是"可能失真"，用后置验证对冲；诚实标注比伪装成真实调研更经得起面试追问。
