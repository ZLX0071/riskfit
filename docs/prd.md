## 1. 背景与问题

**问题陈述**：HK 的年轻散户（持仓满一年，资产散落在券商和 crypto 平台）普遍说不清"我的组合到底有多险"。三个具体表现（来源：模拟访谈，见 `research/user-interviews.md`，假设待 D7 真实测试验证）：

1. 平台给过风险等级，但不解释、不给行动（"富途给我 C+，然后呢？"）；
2. 集中度是最大盲区——月供党和全仓党都不知道自己"侧埋一边"；
3. 对抽象指标无感，对具体历史事件有体感（2022 币灾、Luna）。

**机会**（来源：`competitive-analysis.md`）：风险指标工具不缺，但"跨资产混合分析 + 免登录 + 说人话 + 具名压力情景"无人做整包；moomoo AI 组合体检最接近，但锁死在券商生态内。

**产品定位**：风险教育工具，不构成投资建议。一句话：散户输入持仓，30 秒拿到一份说人话的风险体检报告。

## 2. 目标与成功指标

**v1 产品目标**：完成一次"可信、可懂、可演示"的组合风险体检（可信=数字可溯源；可懂=说人话；可演示=断网也能跑）。

| 类别 | 指标 | 目标 |
|---|---|---|
| 北极星 | 完成的体检报告数 | 上线首周 ≥30 次 |
| 激活 | 落地页→点击示例组合 | >40% |
| 激活 | 进入编辑页→提交组合 | >60% |
| 价值 | 报告页滚动到底（阅读完成） | >50% |
| 信任 | AI 声明区展开率 | >15%（有人看=信任话题有效） |
| 护栏 | 报告生成失败率 | <1% |
| 护栏 | 数据兜底（演示模式）触发率 | <10% |

**埋点计划**（匿名事件，无登录无 PII，匿名 ID 存 localStorage；金额与持仓代码不上报）：

| 事件 | 触发时机 | 关键属性 |
|---|---|---|
| page_view | 各页加载 | page |
| example_click | 点击示例组合 | — |
| portfolio_submitted | 提交组合 | 持仓数、是否含crypto（布尔） |
| report_completed | 报告渲染完成 | 体质分、耗时ms |
| report_scrolled_bottom | 滚动到底 | — |
| ai_disclosure_open | 展开AI声明区 | — |
| report_failed | 生成失败 | 失败环节、是否兜底 |

## 3. 目标用户

- **核心**：P1（多平台散户）、P2（体感型新手）、P4（月供党）、P5（全仓党）——持仓满一年、港美股或 crypto 至少其一。
- **排除**：P6 纯小白（无持仓无从体检）；P3 硬核杠杆用户（要实时预警，属 roadmap，不在 v1）。

## 4. 用户故事与验收标准

### P0（v1 必须）

- **US1 一键示例**：Given 我在落地页，When 点击"示例组合"，Then 系统填入（腾讯+AAPL+BTC）并在 10 秒内出报告；断网时走缓存/快照同样成功。
- **US2 组合编辑**：Given 我在编辑页，When 添加 2–8 个持仓并输入金额，Then 可提交；当持仓<2、>8、金额≤0 或代码无效时，Then 行内错误提示且不跳转。
- **US3 指标计算**：Given 有效组合，When 提交，Then 报告页展示年化波动率、最大回撤、VaR(95%)、集中度及基准对照（vs 恒指/标普500），且数字与命令行验证脚本的输出完全一致。
- **US4 压力情景**：Given 报告页，When 查看情景卡，Then 展示 3 个具名情景（2008级股灾/2022币灾/主导资产腰斩）的预估亏损%与金额，且方法论脚注含代理规则说明。
- **US5 AI 报告**：Given 计算完成，When 生成报告，Then 输出总评一句+三个风险点+三个自查问题；输出中每个数字都能在计算结果 JSON 中找到（后校验通过），校验失败重试≤2 次后回退模板文本，报告永不空白。
- **US6 信任声明**：Given 报告页，Then 固定展示"本报告为风险教育内容，不构成投资建议"与"数字由计算引擎产生，AI 仅负责解释"。

### P1（v1 尽量）

- **US7 相关性热力图**：资产两两相关矩阵可视化。
- **US8 体检进度**：三步进度展示（行情→计算→AI 撰写）。
- **US9 演示模式标注**：使用内置快照数据时，页面明确标注。

### P2（明确不做进 v1，进 roadmap）

分享卡片、多智能体风控委员会、实时预警（P3 的需求）、小白引导（P6 排除依据）、历史穿越沙盘。

## 5. 功能需求明细

指标口径、评分卡分档、压力情景代理规则、AI 层设计、缓存与错误态——**全部见技术方案 spec §5–§7**，本文档不重复。spec 与 PRD 冲突时以 PRD 的范围与优先级为准，口径以 spec 为准。

## 6. 非功能需求

- **性能**：缓存命中下报告页可交互时间 <3s。
- **可靠**：断网/接口故障仍可完成示例组合演示（缓存+快照两级兜底）。
- **合规**：免责声明固定展示；不输出买卖建议（AI prompt 硬约束）。
- **隐私**：无登录；不采集 PII；持仓与金额不落库不持久化。

## 7. 范围外

登录/账户体系、数据库存储、期权衍生品、自由代码搜索、多语言切换、实时行情预警、投资建议。依据：YAGNI + 访谈排除项。

## 8. 风险与开放问题

| 风险 | 缓解 |
|---|---|
| 免费数据接口不稳定 | 两级兜底（缓存→快照）+ 面试前预热缓存 |
| 体质分权重主观 | 权重与分档在 README 公开，标注为可迭代的 PM 决策 |
| moomoo AI 同类功能竞争 | 差异化：跨资产、免登录、教育定位（见竞品分析） |
| 模拟访谈假设失真 | D7 真实用户测试验证洞察 2/5，结果记入复盘 |
