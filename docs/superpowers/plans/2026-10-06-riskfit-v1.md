# RiskFit V1 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 构建组合风险体检工具 RiskFit V1：输入港美股+crypto 组合 → 计算风险指标与压力情景 → AI 生成说人话体检报告。

**Architecture:** Next.js App Router 全栈单仓库。纯函数计算引擎（`src/lib/engine`，可独立用 CLI 验证）；数据层三级兜底（内存缓存→实时接口→内置快照）；AI 层生成后逐数字校验、失败回退模板。前端两路由：`/` 落地页、`/check` 承载编辑/进度/报告三态，持仓可编码进 URL 参数分享。

**Tech Stack:** Next.js 14+ / TypeScript / Tailwind / Vitest / GLM API（OpenAI 兼容接口）/ Vercel 免费档。

**Spec:** `docs/superpowers/specs/2026-10-06-riskfit-design.md`（口径与规则以 spec §5–§7 为准）

## Global Constraints

- 持仓数 2–8；金额统一 USD；输出以百分比为主、金额为辅。
- 数据窗口：股票近 2 年（Yahoo Finance v8 chart 接口）；crypto 近 365 天（Binance `/api/v3/klines`，免密钥）；压力情景按各自窗口另行取数（2007-10-01~2009-03-31、2022-01-01~2022-12-31）。
- 年化：股票 √252，crypto √365（单资产层面）；组合层面按对齐序列 √252（纯 crypto 组合用 √365），脚注说明。
- VaR(95%, 1日)＝对齐组合日收益 5% 分位（线性插值）× 组合市值。
- 评分卡权重：波动率 25% / 最大回撤 20% / VaR 20% / 集中度 20% / 平均相关性 15%；分档表见 spec §5.5，档内线性插值；总分四舍五入到 1 位小数。
- 压力情景代理规则：2008 情景中 crypto 直接套用其 2022 窗口真实收益；主导资产腰斩＝最大持仓 -50%，其余按 `corr × (σ_i/σ_主导) × -50%` 联动。
- 固定文案（逐字）：`本报告为风险教育内容，不构成投资建议`；`数字由计算引擎产生，AI 仅负责解释`。
- 环境变量：`GLM_API_KEY`、`GLM_MODEL`（默认 `glm-4-flash`，按用户开放平台可用模型调整）；GLM 接口 `https://open.bigmodel.cn/api/paas/v4/chat/completions`（OpenAI 兼容）。
- 缓存 TTL 12h（进程内 Map，serverless 冷启动靠快照兜底）；无登录、无数据库、无 PII 持久化。
- 预置资产 16 个（spec §5.1）：`0700.HK, 9988.HK, 0005.HK, 1299.HK, 3690.HK, 1810.HK, AAPL, MSFT, NVDA, TSLA, AMZN, GOOGL, SPY, BTC, ETH, SOL`；基准 `^HSI, ^GSPC`；crypto 映射 `BTC→BTCUSDT, ETH→ETHUSDT, SOL→SOLUSDT`。

## Review Focus

1. **数据三级兜底链**：Yahoo/Binance 抓取失败或返回异常结构时，必须 缓存→快照 逐级回退，任何一级失败都不得让请求 500。测试：Task 6 注入失败的 fetcher 断言回退到快照。
2. **混合日历对齐**：crypto 有周末数据、港美没有，对齐后不得出现 NaN/Infinity。测试：Task 2 用含周末的 crypto 序列 + 股票序列断言输出全为有限数。
3. **AI 编造数字**：LLM 输出含计算结果中不存在的数字或非法 JSON 时，校验必须拦截→重试→模板兜底。测试：Task 8 用 mock 的"编造数字"响应断言校验失败并回退。
4. **退化统计**：价格序列全平（方差为 0）时波动率=0、相关性返回 0，不得产出 NaN 或除零崩溃。测试：Task 3 用常数序列断言。
5. **持仓校验边界**：<2 个持仓、>8 个、金额≤0、未知代码，必须在 API 层拒绝并返回可读错误。测试：Task 9 路由测试覆盖四类非法输入。
